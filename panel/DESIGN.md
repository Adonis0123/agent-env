# 「环境」面板设计约定

面板嵌在 Local Tools 门户里，颜色、字体、圆角和控件都来自门户的共享层（`/_shared/local-tools.css`，规范见门户仓库的 `DESIGN.md`「Panel 复用共享组件」）。本文件只写面板自己的规则：切换控件，和交给 AI 的文字。

## 方向

- 产品：一页看清每台机器上每个 agent 的习惯是否和清单一致，哪里有问题，该谁处理。
- 气质：冷静、精确、可核对。
- 颜色只给状态（缺失、漂移、失败）；控件和数量保持安静，不和状态抢注意力。

## 切换控件

一共三级，全部用共享组件，页面只负责摆放：

| 级别 | 作用 | 组件 |
| --- | --- | --- |
| 视图 | 待办 / 按机器 / 总览 / 关系图 / 插件 | `nav.lt-tabs` + `button.lt-tab`（`role="tablist"` / `tab` / `tabpanel`） |
| 视图内筛选 | 总览「全部 / 只看有问题的」，关系图「全部连线 / 只看有问题的」 | `.viewbar` 里的 `.lt-segmented`（`role="group"` + `aria-pressed`） |
| 侧栏内切换 | 关系图侧栏里一个 agent 的四类习惯 | `.lt-segmented.rp-chips`，四等分 |

### 尺寸

| 项 | 值 |
| --- | --- |
| 纵向节奏 | 标题 → 标签行 → 视图条 → 内容，每一步 `16px`（`.views` 上的 `--step`） |
| 标签行 | 共享层：高 `44px`，内边距 `0 12px`，项间距 `4px`，`14px/500`；选中是品牌色文字。`2px` 下划线是面板自己的一条 `.view-ink`，见「切换动效」 |
| 视图条 `.viewbar` | 最小高 `32px`；控件和图例之间 `24px`，换行后行距 `8px` |
| 分段控件 | 共享层：轨道 `32px`、圆角 `6px`；项 `30px`、圆角 `4px`、内边距 `0 12px`、`13px/500`；选中是浅品牌底加品牌色文字 |
| 侧栏四等分 | 同一个分段控件；项内边距收到 `0 6px`，名称和状态居中紧挨着 |
| 窄屏标签行 | `420px` 以下标签间距收为 `0`（`.views > nav { gap: 0 }`），英文五个标签（To do / Machines / Overview / Map / Plugins）才能在 `390px` 排成一行；标签名保持最短的名词 |
| 点击高度 | 标签 `44px`；分段 `32px`，`760px` 以下 `40px`（用看不见的 `::before` 扩出来，外观不变） |
| 数量 | `12px`、等宽数字、次要文字色；跟在名称后面，为 0 时不显示；不用徽标 |
| 焦点 | 共享层的 `3px` 光环；标签之间用方向键、Home、End 移动 |
| 动效 | 见「切换动效」；悬停和选中的底色 `120ms`（共享层） |
| 宽度 | 所有视图共用一个 `1240px` 的列（`.wrap`）：标题、标签行、视图条、内容、页脚的左右缘在每个视图里都对齐。这个宽度由关系图定：图 `672px` + 间距 `32px` + 侧栏至少 `400px`。正文行宽用 `72ch` 这类约束收窄，不缩列 |

### 规则

1. 页面 CSS 不写 `.lt-` 选择器（`index.test.ts` 有断言）。要改标签或分段控件的外观，改共享层。唯一例外是下划线：共享层的下划线画在每个标签上，只能跳，不能滑，所以面板用 `.views > nav.has-ink > [role="tab"]::after { content: none }` 关掉它，换成自己的 `.view-ink`。共享层以后自带滑动下划线时，删掉这条和 `.view-ink`。
2. 视图的第一块内容顶部不留白，间距只由 `--step` 给。新视图要筛选就放进 `.viewbar`，不另起一个条。
3. 切换视图时，标题、标签行、视图条每一帧都不能移动。不给单个视图另设列宽，也不让某个视图的内容伸出列外（试过只放宽关系图：门户里图比标题行左出一截，侧栏的按钮贴到窗口边）；视图放不下时在列内换布局，如关系图在 `1152px` 以下把侧栏放到图的下面。内容不做位移动画。
4. 同一级的切换只用一种组件。不新写长得像分段控件或标签的类。

### 切换动效

切换时只有下划线在动。视图在点击的同一帧直接换，不淡入淡出，其他东西原地不动。

| 项 | 做法 |
| --- | --- |
| 下划线 | 标签行里一条 `.view-ink`（`1px` 宽、`2px` 高），脚本量出选中标签文字的左边缘和宽度，写成 `transform: translateX() scaleX()`。`200ms`、共享层的 `--ease-out`。只动 `transform`，由合成器执行，主线程在排新视图时它照样滑。位置取整到设备像素。第一次摆放、刷新后、窗口改变大小时直接到位，不做动画；`prefers-reduced-motion` 下不滑。`showTab` 先量位置再改页面，一次切换只排一次版 |
| 内容 | 同一帧换：旧视图 `hidden`，新视图显示，不透明度始终是 `1`，没有任何过渡 |
| 滚动位置 | 页面滚了一点再切到更短的视图，页面高度不够，浏览器会把页面拉回顶部，标签行跟着跳。`showTab` 给 `#content` 补 `min-height`，保住滚动位置；滚回顶部时去掉。算法在 `model.ts` 的 `scrollHold`。标签行已经滚出屏幕时不补 |
| 滚动条 | `html { overflow-y: scroll }`：滚动条占宽度的系统上，滚动条的位置一直留着，长短视图切换时页面不横移。共享层的 `scrollbar-gutter: stable` 是同一个目的，这条是它不生效时的保底 |

不要给视图加进场动画，两种都试过，都会闪：

- 新内容从透明淡入（加不加位移都一样）：旧内容先消失，内容区有一帧是空的，再浮出来。加了位移，视图条还会跟着动 `4px`。
- 新旧交叉淡化（View Transitions API）：没有空白帧，但中间约 `40ms` 新旧两层各半透明叠在一起，文字发灰，看起来还是闪一下；每次切换还多出一帧 `20–35ms` 的长帧（浏览器给旧视图拍照）。写法留在任务记录里，要恢复时注意三点：只拍标签行下面的部分，`:root` 和标签行不能进图（进图的元素淡化期间点不到）；`::view-transition-group()` 用 `animation-name: none`，不用 `animation: none`（简写会清掉 fill mode，淡化结束时旧视图满不透明度闪回）；页脚要和视图在同一张图里。

下划线不用 CSS keyframes：连点时会从头开始，transition 才能半路改道。

### 验收

`390px` 和 `1440px` 下逐个点五个视图，量三件事：标签行的左边缘不变；标签行到第一块 `16px`；视图条到内容 `16px`。页面不横向溢出。再用键盘走一遍：方向键换视图，Tab 进筛选，焦点环可见。

改了切换相关的 CSS 或 `showTab`，还要逐帧量：从点击起 `400ms` 内，每一帧记录标题、标签行、每个标签、视图条、第一块内容的位置，以及页面的 `clientWidth`、`scrollY`。五个视图两两切换共 20 种，宽度 `1440 / 1280 / 1152 / 1100 / 390`，滚动条占宽度和不占宽度各一遍，页面先滚 `48px` 再切一遍。标题、标签行、视图条的位移必须每一帧都是 `0`。只量切换前后的静态位置发现不了抖动。

### 参考

- Primer UnderlineNav（https://primer.style/product/components/underline-nav/guidelines/ ）：标签栏紧贴它管的内容，宽度不超出内容。
- Primer SegmentedControl（https://primer.style/product/components/segmented-control/guidelines/ ）：筛选要有一项显示全部；名称用尽量短的名词。
- Geist Tabs（https://vercel.com/geist/tabs ）：手机上一行 3–4 个标签；数量不写进名称，为 0 时隐藏。
- Emil Kowalski 的动效规则（https://github.com/emilkowalski/skills ）：界面动效不超过 `300ms`；能被打断的用 transition，不用 keyframes；`transform` 直接写在元素上，不写在父级的 CSS 变量里；键盘触发的操作不做动画。

## 交给 AI

看面板的人不敲命令，事情都是告诉 AI 去做。页面上有命令的地方，主按钮复制的是一段给 AI 的话（`ai-copy.ts`），命令只作为次要的代码文字留着。

### 复制出去的话

每一段单独粘给 AI 都必须是对的：

| 规则 | 做法 |
| --- | --- |
| 说清在哪运行 | 本机的命令带目录（`在 <目录> 目录里运行 …`）。一件事有几步时按步骤写，每步按自己的 `who` 定地点：`ai` 是本机的目录，`other_env` 是点名的那台机器，`user` 是「这一步由我来做」，不替它猜机器 |
| 顺序不丢 | 多步的事编号列出，没有命令的步骤写步骤原文。引擎的修法是一句话（里面可能有几条命令）时整句引用，只给一个按钮，不按命令拆 |
| 写操作先给看 | 命令不是只读的（`readsOnly`），句子就带「先给我看，等我同意再做」。写操作步骤带的是演练命令，句子里叫它「演练用」 |
| 「你」是谁 | 引擎的步骤和修法是写给人看的。引用到的文字里有「你」，就加一句：其中的「你」指我本人，不是 AI |
| 按钮名 | 整件事是「复制给 AI」，步骤里的是「复制这一步给 AI」，句子里写明是第几步、共几步 |

### 工作目录

目录在运行时算出来（`source.ts` 的 `workFolders()`），仓库里不写任何人的路径。找法和引擎一致（`engine/agent_env.py` 的 `manifest_arg`、`engine/overlay.py`）：设了 `AGENT_ENV_MANIFEST` 就用它，可以是任意路径；否则从引擎目录起最多往上 3 层找 `manifest/habits.toml`。

| 情况 | 页面和句子 |
| --- | --- |
| 找到清单 | 命令在个人仓库运行（它有自己的 `bin/agent-env` 时），否则在引擎目录运行 |
| 清单来自 `AGENT_ENV_MANIFEST`，那个文件夹没有自己的 `bin/agent-env` | 命令在引擎目录运行，每条 `bin/agent-env` 命令前带 `AGENT_ENV_MANIFEST=<路径>`；事实里有 `command_prefix` |
| 没找到清单 | 不把引擎目录说成个人目录：页脚（读不到状态时在错误块里）写明没找到个人清单并给一句可复制的话；每段带命令的话末尾提醒 AI 先找到清单；事实里 `manifest` 为 `null` |

### `ai-tasks.json` 的 `"cwd": "engine"`

`cwd` 是门户启动 AI 任务时的起始目录。`"engine"` 的意思是：门户让 AI 从门户自己的任务目录开工，不解析任何路径，所以这个文件里不用写谁的目录。AI 该去哪干活由事实带过去：每条事实有 `workdir`（运行命令的目录），插件那条还有 `manifest`（要改的清单文件），四个预设的 pointers 都写明按它们来。

要让 AI 一开始就在个人仓库里开工（这样它会先读那里的 `AGENTS.md`），在自己私有的 `portal.json` 里给这一页设 `ask.cwd`。它优先于 `ai-tasks.json` 的 `cwd`，个人路径留在私有配置里。
