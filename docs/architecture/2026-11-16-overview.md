| Name | Kind | Responsibility | Code path |
| --- | --- | --- | --- |
| Personal layer | external input (the user's private repository and the paths the manifest's `[sources]` points to) | holds the manifest `manifest/habits.toml` and `repos.json`; where the rules source `rules_src`, own skills and other sources live is set by the manifest's `[sources]` | not in this repo; located by `engine/overlay.py`, example in `examples/demo/`, template in `profiles/_template/starter/` |
| `bin/agent-env` | shell entry | starts `engine/agent_env.py` with `AGENT_ENV_PYTHON` or `python3` | `bin/agent-env` |
| CLI dispatch | Python module | parses the subcommand, settles the manifest path (`--manifest`, `AGENT_ENV_MANIFEST` or the default location), calls the modules, and turns errors into FAIL lines with a 「修复：」 (fix) | `engine/agent_env.py` |
| Personal layer lookup | Python module | walks up at most 3 levels from the engine root to the nearest `manifest/habits.toml` | `engine/overlay.py` |
| Manifest and rules source reader | Python module | reads the TOML manifest and resolves the `[sources]` paths, joins the rules source's Markdown files in `[rule_sections]` order into one rules text, selects sections by role | `engine/habits.py` |
| Manifest check | Python module | `check`: validates schema, rules, environments, plugins, targets and MCP item by item, prints PASS / WARN / FAIL, never crashes on errors | `engine/habits_check.py` |
| Plugin build and publish | Python module | builds rule sections and skills into plugin folders, runs the privacy scan, publishes as build → scan → commit → push and keeps a ledger; makes the pointer rule | `engine/plugins.py` |
| Third-party skill copy | Python module | copies third-party skills into a plugin with their provenance and license, compares with upstream HEAD | `engine/vendor.py` |
| Local compose | Python module | merges the rules source's sections and each plugin's `rules_file` into one rules file in the target's plugin order, reports overrides | `engine/compose.py` |
| Render and write | Python module | produces a target's rules text, compares with `--check`, and with `--write` snapshots first, then writes atomically | `engine/render.py` |
| Pull kit delivery | Python module | makes `pull.conf` and the install steps; on the remote host backs up, installs the kit, runs a preview pull, and switches on the timer only when the preview hash matches | `engine/pull.py` |
| Remote exec channel | Python module | runs one sh script on the remote host through the manifest's `exec` command prefix and sends files in chunks through `send`; also delivers the whole rules file to remote targets that do not use plugins | `engine/remote.py` |
| Pull script and timer | POSIX sh script + systemd user units | on the remote host every 30 minutes fetches each plugin repository, joins their `AGENTS.md` in order, replaces the rules file only when its content changed, and writes `pull.status` | `features/plugin-pull/` |
| State directory | local file storage | holds built plugins, the publish ledger, work clones, snapshots, text waiting to be pasted, delivery records, eval results and the repository visibility cache | `engine/state.py` (location: `$XDG_STATE_HOME/agent-env`) |
| Plugin repositories | external git repositories | one repository per plugin, with one visibility (public, personal, company); remote hosts and cloud-hosted bots take rules and skills from here | not in this repo; pushing is in `engine/plugins.py` |
| Own-machine target | local file | the target's `rules_output`; other hosts on the same machine read it through a link or a hook | not in this repo; written by `engine/render.py`, checked by `engine/expect/composed.py`, `engine/expect/link.py`, `engine/expect/contains.py` |
| Cloud-hosted target | external service (vendor-hosted bot) | keeps the pointer rule in its own memory and pulls the plugin repositories itself as the rule says | not in this repo; the pointer rule text is in `engine/plugins.py`, the record flow in `engine/agent_env.py` |
| Doctor | Python module | `doctor`: detects the current environment and computes one cell per expectation of every target; a remote environment is checked by one combined script in one round trip | `engine/agent_env.py`, `engine/remote.py` |
| Expectation registry | Python package | one module per expectation kind (14 in all), each with validation, a local check and a remote check | `engine/expect/` |
| Cells | Python module | defines the five states synced, customized, drift, missing, unknown and the cell structure | `engine/cells.py` |
| MCP comparison | Python module | read-only comparison of the MCP servers a target should have with those enabled in the host config | `engine/mcp.py` |
| Status branches | git refs | one `status/<env>` branch per environment, holding one `status.json` only | read and written in `engine/agent_env.py` |
| All status | Python module | `status --json --all`: merges this machine's live result, the cloud-hosted environments driven from this machine and the other environments' status branches, and adds issues, glossary, relations and the plugin view | `engine/agent_env.py` |
| Issue builder | Python module | turns cells into things to do, deciding from data tables who acts and how it is worded | `engine/issues.py` |
| Plugin view | Python module | prepares the data for the panel's plugins tab: repositories, build and publish state, what each environment gets; caches whether a repository is public or private | `engine/plugins_view.py` |
| Behaviour evals | Python module | `eval`: runs behaviour spot checks on targets from the manifest's cases; `status` reads the results | `engine/evals.py` |
| Promote | Python module | `promote`: scans the memory, permissions and new skills hosts have learned, and writes draft proposals to feed them back into the sources | `engine/promote.py` |
| Company skill install | Python module | copies company skills into a target's skill folder, with backup and rollback | `engine/company_skills.py` |
| Environments panel | TypeScript (no dependencies) | read-only page: runs `status --json --all` or reads the file `AGENT_ENV_STATUS_FILE` names, parses it and renders the to do, by machine, overview, relations and plugins tabs | `panel/index.ts`, `panel/source.ts`, `panel/model.ts`, `panel/page.ts`, `panel/plugins-view.ts` |
| Panel file preview | TypeScript module | read-only preview of files listed by the last 8 renders; the page sends an id, never a path | `panel/files.ts` |
| Panel standalone server | TypeScript script | serves the same handler on its own local HTTP server, without the portal | `panel/dev-server.ts` |
| Runbook skill | document | the manual an agent follows when operating the engine | `skills/agent-env/SKILL.md` |
| Privacy scan CI | GitHub Actions workflow | scans this repo with gitleaks on every push and PR | `.github/workflows/privacy-scan.yml`, `.gitleaks.toml` |
